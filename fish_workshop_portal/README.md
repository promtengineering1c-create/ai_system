# Fish Workshop Portal (Цех рыбопереработки)

Омниканальная витрина, B2B-портал и интеграционный шлюз для цеха рыбопереработки.

## Требования к окружению

* Python 3.12+
* [uv](https://docs.astral.sh/uv/) (менеджер пакетов Python по стандарту PEP 621)
* Docker & Docker Compose

## Быстрый старт (Локальная разработка)

### 1. Клонирование репозитория и установка зависимостей

```bash
git clone <repository_url>
cd fish_workshop_portal
uv sync
```

### 2. Настройка переменных окружения

Конфигурация построена на каскадной загрузке доменных настроек (`pydantic-settings`):
* По умолчанию активен режим разработки (`APP_ENV=development`).
* Загружаются переменные из `.env`, затем переопределяются значениями из `.env.development`.

```bash
cp .env.example .env.development
# При необходимости отредактируйте параметры подключения в .env.development
```

### 3. Запуск инфраструктурных сервисов (PostgreSQL, Redis)

```bash
docker compose up -d postgres redis
```

### 4. Применение миграций

```bash
uv run python manage.py migrate
```

### 5. Запуск сервера разработки

```bash
uv run python manage.py runserver
```

Веб-витрина доступна по адресу: `http://127.0.0.1:8000/`.

## Архитектура и контракты обмена (1С <-> WEB)

Взаимодействие строится на базе единых Pydantic-контрактов (`services.exchange.contracts`) через два взаимозаменяемых транспортных канала:
1. **REST JSON API:** синхронный эндпоинт `POST /api/v1/exchange/` с авторизацией по Bearer-токену.
2. **Файлово-пакетный шлюз:** обмен парами файлов `*_meta.json` и `*_payload.json`/`.xlsx` через директории `/exchange/` (`1c_to_web`, `web_to_1c`, `archive`, `error`).

### Типы событий (`event_type`):
* `PRICE_SYNC` — выгрузка товарной матрицы регулярного ассортимента из 1С на сайт.
* `SUB_SYNC` — передача подтвержденных профилей и анкет подписчиков из Django в 1С.
* `UNSUB_EVENT` — передача событий отписки пользователей из Django в 1С.
* `ORDER_CREATE` — передача B2B и групповых заказов.
* `ACK_RECEIPT` — подтверждение успешного приема и фиксации пакета в БД (квитирование).

## Фоновый воркер

Фоновый процесс очереди задач PostgreSQL и обработки файлового шлюза запускается командой:

```bash
uv run python manage.py runworker
```
